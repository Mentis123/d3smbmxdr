# Coastwater · facilitator run sheet

New rooms use `coastwater@2`: six dilemmas, two screens per scenario, about 40 minutes. Existing `coastwater@1` rooms retain the original questions, options, reports and 33-screen sequence. Create a new room to run the shorter edition.

## Open the two screens

Open `/decision-room/coastwater`, choose Facilitate, enter the facilitator key and create a room with one device per table. New rooms open the private facilitator console. Existing full admin controls have an **Open facilitator console** button above session timing.

Keep the console on your private screen and use **Open audience display** for the projector. Both views follow the room's shared presentation position. You can alternatively advance from the presentation with controls. Next/Back and keyboard navigation update the room; Back reviews earlier screens without reopening voting or changing answers.

The welcome screen shows **bit.ly/4Bg3QuC**, the room code and a direct join QR code. Participants enter the code, choose their table and join.

## Run the shorter edition

Allow five minutes to introduce the setting and joining, five minutes per scenario, and five minutes to close. Session date, start time and length can be adjusted in full room controls, using Australia/Sydney time. The agenda adapts to the length and actual start.

Each scenario has two screens:
1. **Situation and decision.** All facts needed for the dilemma, the concrete decision, four defensible options and the cost of each. Reaching the screen opens voting. Tables choose, add a sentence of reasoning and confidence, then lock.
2. **Room discussion.** Next closes voting and publishes the split. Ask which downside each table accepts and what evidence or condition would change its decision. Next proceeds directly to the next scenario.

No mandatory reveal or boundary screen. Facilitator notes contain one optional probe for deeper discussion. Capture appetite notes privately using the optional disclosure; the closing screen prompts a read-back of accepted downsides, conditions and unresolved differences. It is an emerging view of appetite, not an approved policy or a score.

## Monitor and curate

The private console shows joined, reading/drafting and locked tables, plus incoming saved drafts and locked comments. Select at most two locked comments for projection. They remain queued while voting is open, then appear on the discussion screen. Drafts and unselected comments never appear there. Selections can be removed or replaced during discussion. Reopen a locked table before publication if its answer needs changing.

The audience display uses the room display token and cannot perform facilitator actions. Admin-key fallback still returns the filtered display payload. Full admin retains reports, exports, resets and timing controls.

## Timer

**Show audience timer** defaults off for Coastwater, including existing rooms. It applies to projector/presentation and participant devices and persists in the room. Private facilitator timing remains visible. Enabling the timer does not close voting or advance slides automatically. Existing other editions retain their timing behaviour.

## Recovery and records

Votes, rationales, schedule, timer setting and live presentation position persist in the room using the existing workshop storage. No schema migration is needed. Stale presentation actions are rejected and refreshed rather than skipping a screen.

Optional appetite notes are stored in the browser and synchronised between tabs on that browser. Export them before changing devices; they are not saved to the server. Reports and CSV resolve the room's pinned content revision. The full presentation can be rehearsed without a room or live votes.
